# 05 · 失败路线全集 + 症状排查（NSUNSC / XFBIN 角色 Mod）

适用：`NARUTO X BORUTO Ultimate Ninja STORM CONNECTIONS`（`NSUNSC.exe`）+ NSC Mod Manager + `xfbin_lib` + `cc2_xfbin_blender`。
本文是**排查手册**：先查第 1 节失败路线表（"我是不是正在走这条"），再查第 2 节症状速查表（"现在看到什么、下一步查什么"）。
所有条目来自本仓库的真实调试记录：手鞠 / 天天 / 校服天天 / 井野02 / 泳装小南 / Kushina-Rin 投技 / Mei-井野投技 / Blender 导出。

## 1. 失败路线全集表（核心，按"我打算这么做"查）

> **读完先记住三条总则**：
> ① **动作稳定性 > 外观微调**——任何导致"选人消失 / 卡加载 / 崩溃"的改法一律先回退；
> ② 最稳路线 = **模型文件保留来源角色骨架 + 只做等长前缀改名 + 攻击文件用目标角色原版**；
> ③ **"模型消失 / 无限加载"先查文件名、角色位配置、`prm_mot` 大小字段、冲突 mod，不要先动材质。**

### 1.1 骨架 / 角色位 / 配置类

## 2. 症状 → 首要怀疑 → 动作 速查表

| 症状 | 首要怀疑（按先后顺序） | 动作 |
|---|---|---|
| **选人界面模型消失** | ① `BaseModel` 写成来源代码（F4）② 模型文件名与角色位不匹配（F5）③ **`prm_mot` 大小字段写错**（F26）④ CPK 打包不完整（F32）⑤ 多 mod 冲突（F33） | 先**回退配置**到上一次能用的；再核对 `Characode/BaseModel/文件名`；再验 `prm_mot` 大小字段 = 块长 − 4；再看是否只启用了一个 mod。**不要先动材质** |
| **进战斗一直卡加载** | 同"选人无模型"①②③④，外加：来源是**新角色位**（F2）、`dtngbod1` 被改名（F5） | 退出游戏 → 只启用一个 mod → 重新打包；逐项核对角色位配置与 `prm_mot` 字段 |
| **进战斗闪退 / 崩溃** | 走过**重绑骨架**路线（F1）、新角色位（F2）、材质 parent 指错 | 回退到"等长前缀改名 + 保留来源骨架"；崩溃点几乎总在骨架/材质引用 |
| **能进战斗但外观没变** | ① 改错文件（没放进 `Resources\Files\data\spc\`）② 看错角色位/服装槽（`_00` 做了、`_01` 没做）③ 方向搞反（目标/来源 T、S 互换）④ 改了没重新打包（F9） | 确认落盘路径与文件名 = **目标槽位名**；确认 CPK 时间/大小已变 |
| **动作变成来源角色的**（普通攻击/投技/技能变了） | 漏保留目标角色原版攻击文件 | 补回目标原版：`2karbod1c.xfbin`（连段）、`2karbod1l.xfbin`（投技）、`2karbod1s.xfbin`（技能）、`2karbod1acc.bin.xfbin`（配件） |
| **普通攻击失效 / 脸型被拉大** | 直接套用了来源骨骼（F3） | 回退；来源与目标骨架不同构时不要硬套 |
| **眼睛透明 / 没有贴图** | ① 材质贴图槽数量（1 组 vs 2 组，F16）② 贴图格式（DXT5 / RGB565 / RGBA8，F17）③ 贴图名与材质引用不一致（F12）④ 误改成 `2teneye`（F13） | 先确认**贴图可见性**，再动坐标；把材质/贴图名统一成目标命名，必要时重建材质槽或转格式 |
| **眼睛 / 牙齿位置错（下巴 / 脚底 / 脖子）** | 刚性网格骨骼约定不同，未做坐标烘焙（F23） | 见第 6 节：烘焙来源→目标骨骼变换进顶点 + 包围球同步 + **`lod0` 与 `lod1` 都改** |
| **五官整体飘到脸外 / 下巴下方** | 骨骼/节点前缀被批量改坏（F6） | 恢复 `dtng00t0` / `dtng_` 前缀，只改必要位置 |
| **嘴巴（牙齿/牙龈）外凸** | 坐标调整打到了错的对象 | 优先**隐藏嘴部块**（见下）；用户要求保留嘴巴时走坐标准确烘焙 + 沿 Y 往脸内 ≈ +0.010 |
| **嘴巴消失了、说话没口型** | 隐藏方案是"预期行为"，但你改的是可视需求 | 两条路二选一，**先问用户**：要保留嘴巴 ⇒ 坐标烘焙；只要不难看 ⇒ 隐藏 `tongue / lower teeth / upper teeth` → `hidden / hiddenlower / hiddenupper` |
| **眼睛出现尖刺 / 平面突起** | 只移动了局部顶点（F20） | 移动**完整形状**（含 lod1），不要逐点扫 |

## 3. `prm_mot` 大小字段：专项 + 字节级取证

**规则**：`prm_mot` 块头部 **offset 2..4（u16 大端）= 块长度 − 4**。
写错的唯一症状就是 **"选人界面模型消失 + 进战斗一直卡加载"**（解析越界）。

同一文件里所有块都遵守该规律（实测本仓库香磷 `prm`）：

| 块 | 块长度 | 头部字段 | 关系 |
|---|---|---|---|
| `awa` | 2412 | 2408 | −4 |
| `prm_mot`（香磷原版） | 40064 | 40060 | −4 |
| `prm_mot`（Rin 投技移植版，mod 内） | **40352** | **40348** | −4 |
| `etc` | 676 | 672 | −4 |
| `sklslot` | 3745 | 3741 | −4 |

取证方式（`<游戏目录>\codex_tmp\docgen\probe_prm_mot.py`，用 `xfbin_lib` 读 `NuccChunkBinary` 后打印 `len(data)` 与 `struct.unpack_from(">H", data, 2)`；本 skill 的 `scripts/dump_xfbin.py --params` 可做同样的事）：
块数据布局实测为 `[2 字节 0x0000][u16 大端 = len−4]["ver0.000"…]`。
Rin 投技 mod 的 `2karprm.bin.xfbin`（63997 字节，原版 63697）里该字段正是 `40348`，块长 `40352`。

**投技条目移植的取证判据**（实测，可直接用）：
把 `PL_ANM_THROW_BEGIN` / `PL_ANM_THROW_SUCCESS_ATTACKER` / `PL_ANM_THROW_SUCCESS_VICTIM` 三段按"到下一个 `PL_ANM_XXX`（`PL_ANM_AWAKE_S`）为止"切出来比较——

| 文件 | 三段长度 | `4rin` 残留 | 块长 / 条目数 |
|---|---|---|---|
| 香磷原版 `2karprm.bin.xfbin` | 628 / 916 / 212 | 0 | 40064 / 91 |
| Rin 源 `4rinprm.bin.xfbin` | **1236 / 596 / 212** | 123 | 46152 / 93 |
| 移植后的 `2karprm`（mod 内） | **1236 / 596 / 212** | **0** | 40352 / 91 |

⇒ 三段长度与源**完全一致**且无源前缀残留 = 移植正确。

修正写法（唯一正确形式）：

```python
import struct
struct.pack_into(">H", mot, 2, len(mot) - 4)   # 写完块内内容后必须重算
```

其余校验：`prm` 条目数不变（香磷保持 91）；除投技区域和大小字段外 `prm_mot` 其余字节与原版一致；
其他参数块（`awa` / `etc` / `hit` / `load` / `skl` / `sklslot` / `spl`）**逐字节不变**；**重读输出再验一遍**。

## 4. 调试方法论 / 纪律

1. **每次只改一个方向或一类资源**，改前先备份"当前能用的"xfbin 到 `<游戏目录>\codex_mod_backups\`。
   仓库里的证据就是这一串阶段性备份：`school_dtngbod1_before_eye_all_shapes_plusZ_*` → `..._plusY_*`
   → `..._before_mouth_chunk_rename_hide_*` → `..._before_mouth_local_Y_hide_*`；
   命名格式 `before_<改什么>_<时间戳>.xfbin` 让回退一步到位。
2. **落地顺序固定**：① 选人界面能显示模型 → ② 能进战斗 → ③ 动作归属正确（攻击/技能/奥义是目标角色的）
   → ④ 才是眼睛/嘴巴的外观微调。**任何一步把 ①② 弄坏的改动，立刻回退**。
3. **"模型消失 / 无限加载"的排查顺序**：文件名 → 角色位配置（`Characode`/`BaseModel`）→ `prm_mot` 大小字段
   → 冲突 mod / 打包完整性 → 最后才怀疑材质。**反过来查等于白折腾。**
4. **先分清"贴图问题"还是"位置问题"**：眼睛区域**没有贴图** ⇒ 材质/格式问题；
   贴图**可见但位置错** ⇒ 坐标烘焙问题。先确认贴图可见性，再动坐标。
5. **嘴部问题优先试隐藏，不急着改坐标**；只有用户明确要求"保留嘴巴"时才走坐标路线。
6. **验证要逐字节**（不是"看起来对了"）：
   - 贴图数据、骨骼（coord）数据应与原版**完全一致**，除预期改动外无差异；
   - 手鞠案例实测：除两个眼睛材质外，**其余材质字节完全一致**；
   - Blender 重新导入复核：身体/脸网格不变，只有该动的部件按预期偏移；
   - 输出文件大小可作指纹（手鞠成功版 `2karbod1.xfbin` = **3815970 字节**）。
7. **测完再确认一次启用状态**：只启用目标 mod → 退出游戏 → 打包 → 进游戏看**目标角色位的那套服装**。

## 5. 轴向陷阱（这套模型）

| 方向 | 含义 | 依据 |
|---|---|---|
| **Z** | 更接近**上下**方向 | 天天案例：先大幅 Z 上移把眼睛从下巴带到鼻子附近，再小幅 Z 上移到眼位 |
| **Y** | **真正的内外方向** | 天天 / 校服天天 / 手鞠三个案例一致：**`+Y` = 往脸内收** |

- **眼睛内收要沿 `+Y`，改 `Z` 会让眼睛往额头/头发方向偏。**
- 天天案例的累计量：**Z +11.90、Y +1.90**；手鞠案例的 dy 全为**正值**（+0.39 ~ +1.06）也是"往脸内"。
  ⇒ 两案例方向一致（Z 正=上、Y 正=内），**但数值不可机械套用**：换角色/换文件必须**重新定位 eye chunk**。
- **必须移动完整的眼睛/表情形状**，只挪几个顶点会出尖刺。
- 找 eye chunk 的筛法（big-endian float）：`x∈[-20,20]`、`y∈[-20,10]`、`z∈[120,175]`；
  天天成功版的区间（**仅供参照，不要照抄**）：`eye_l_lod0: 1923600-1925819`、`eye_r_lod0: 1925920-1928143`、
  `eye_l_lod1: 2743184-2745384`、`eye_r_lod1: 2745488-2747684`。

## 6. 刚性网格的骨骼约定差异（眼睛/牙齿跑到脚底、脖子的根因）

**两类约定**：

| | 目标角色（如香磷） | 来源（如小南） |
|---|---|---|
| 骨骼位置 | **在原点** | **在头部** |
| 顶点数据 | **世界位置直接写在顶点里** | 只是骨骼的**局部小偏移** |
| 直接混配的结果 | — | **眼睛跑到脚底、牙齿跑到脖子** |

**修法（照做）**：
1. 把"**来源骨骼矩阵 → 目标骨骼矩阵**"的变换**烘焙进顶点数据**；
2. **包围球同步烘焙**；
3. **`lod0` 与 `lod1` 都要改**（`eye_l/eye_r/eye_*_lod1`）；
4. 骨骼**带旋转**时（如手鞠下牙齿约 **10°**），偏移要**按骨骼旋转反算到局部空间**，否则世界落点偏；
5. 验证锚点：眼睛世界 `z=1.551`、上牙齿世界 `z=1.494`，与小南原模型**完全一致**。

手鞠案例的最终烘焙量（原始 NUD 坐标，cm = Blender 米 ×100）：

| 部件 | dx | dy | dz | 说明 |
|---|---|---|---|---|
| `eye_l` | −0.49 | +0.43 | −1.79 | 含 `eye_l_lod1` |
| `eye_r` | +0.02 | +0.39 | −1.96 | 含 `eye_r_lod1` |
| `upper teeth` | −0.08 | +1.03 | −1.37 | 骨骼无旋转 |
| `lower teeth` | −0.06 | +0.77 | −1.50 | 骨骼约 10° 旋转，已反算局部；世界 dy≈+1.02 |
| `tongue` | −0.05 | +1.06 | −1.21 | 皮肤绑定 `tongue01~04` |

**隐藏嘴部的兜底写法**（改成 `hidden*` 后，游戏不再驱动/显示这些部件）：

```
2kar00t0 tongue      -> 2kar00t0 hidden          # 校服天天：dtng00t0 hidden
2kar00t0 lower teeth -> 2kar00t0 hiddenlower     #            dtng00t0 hiddenlower
2kar00t0 upper teeth -> 2kar00t0 hiddenupper     #            dtng00t0 hiddenupper
```

检查：文件里应**仍能看到 `hidden / hiddenlower / hiddenupper`**，而原 `tongue / lower teeth / upper teeth` 不再作为可见块加载。
另有一条已修案例：把牙齿/舌头网格**加回**并一一对应到目标骨骼的 `upper teeth / lower teeth / tongue`，
可恢复说话动画（去掉它们会留下口腔空腔）。
