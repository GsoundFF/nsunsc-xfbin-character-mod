# ③ 自己的模型替换（Blender 自制 / 外部模型）

**模型不是游戏自带的，而是你自己在 Blender 里做的、或从外部拿来的（MMD、其他游戏、
别人分享的裸模型）。**

这一层比 ①/② 复杂得多，因为它必然涉及**顶点、骨骼、权重、贴图**中的至少一项。
本文档的核心结论先说：

> **能不重绑骨架就不重绑。** 优先走"**保留来源骨架 + 等长前缀改名**"
> （和 ① 同一条路，见 `01-original-model-swap.md`），
> 只在纯改名确实做不到时才进 Blender 做重绑。

---

## 0. 先决定走哪条子路线

| 子路线 | 适用 | 风险 | 本文档章节 |
|---|---|---|---|
| **A. 外部模型保留自己骨架 + 等长改名** | 外部模型的骨架**核心骨骼与目标同名** | ★ 低（推荐） | 第 1 节 |
| **B. 外部模型重绑到目标骨架** | 外部模型骨架完全不同，或需要精确共用目标骨架 | ★★★ 高（曾实测失败） | 第 2 节 |
| **C. 在原模型上改顶点（脸型/身材/五官位置）** | 模型已经是本作格式，只想微调 | ★ 中 | 第 3 节 |

判断方法：把两个模型的 `Coord` 块骨骼名都 dump 出来，比对核心骨骼
（`pelvis / spine / neck / head / upperarm / forearm / hand / thigh / leg / foot / toe0`）。

```
香磷 227 骨  vs  小南泳装 219 骨   → 核心骨架同名，28 根小南独有骨骼（hair00~10/tail/eri/joe/lip）
香磷 227 骨  vs  手鞠 200 骨       → 核心同名，可整文件等长改名
```

---

## 1. 子路线 A：外部模型保留自己骨架 + 等长改名（推荐）

**这是"泳装小南 / 天天 / 手鞠"案例最终收敛到的路线，也是唯一一次通过游戏验证的路线。**

要点：
1. 外部模型文件（如 `2knnbod1.xfbin`）内部前缀整体改名到目标代码（`2knn` → `2kar`）；
2. **骨架用外部模型自己的**（不重绑），权重不动；
3. `BaseModel` 与模型文件名用**目标代码**（`2kar`）——因为文件已经改名了；
4. 材质与贴图名**统一改成目标的命名习惯**（`2karbody / 2kareye / 2karcloth`），
   引擎按目标角色的名字找贴图；
5. 攻击文件用目标角色原版（同 ① 的规则二）。

**注意**：如果外部模型的贴图名与目标**不一致**，必须一起改名，
否则会出现"眼睛贴图消失"这类现象（贴图名与材质引用不一致）。

---

## 2. 子路线 B：重绑骨架（★ 高风险，最后手段）

> **实测失败记录（务必先读）**：把手鞠网格重绑到香磷 227 根骨骼后，
> **选人界面选到人物没有模型，游戏崩溃**。改用等长改名（保留手鞠自己的骨架）后一次通过。
>
> 另一条失败记录：用 `Character Roster Editor` 把来源做成新角色、动作挂目标 ⇒
> **选人界面无模型、进战斗卡加载/闪退**。

**所以：重绑只在"核心骨骼不同名、等长改名必然错乱"时才做，并且先做最小可测版本。**

### 2.1 骨骼映射规则

```
来源骨骼  2knn00t0 pelvis     →  目标骨骼  2kar00t0 pelvis
          （逐名映射；同名直接对应，191/219 根是直接同名）
```

- **同名骨骼直接一一对应**（去掉第一个 token 后比较名字：
  `'OBJ_2szw00t0 head'` → `'head'`）。
- **左右骨骼同名时**（`clavicle` / `hand` 等）**必须按出现次序映射**（第 N 个 `clavicle`
  → 目标第 N 个 `clavicle`），用"先到先得"会把左右手臂都绑到同一根骨上 ⇒ **模型塌成一团**。
- **来源独有骨骼**（`hair00~10 / tail / eri / joe / lip` 等）按就近原则映射到
  `head / upperarm / neck / 根骨骼`；映射不到目标骨架的骨骼，绑到 **`pelvis`** 最自然。
- 顶点权重按目标骨骼**合并重映射**；
- 空对象的 `mesh_bone` 与父骨骼改成目标骨骼名；
- clump 的模型列表/分组可用来源结构，但**骨骼坐标沿用目标原值**。

### 2.2 重绑后的顺序（重要）

1. **先只测"选人有没有模型 + 能不能进战斗"**——这一步不通过，后面全白做；
2. 再测普通攻击/技能/奥义动作是否正常；
3. **最后**才管眼睛/嘴巴/脸型细节。

## 3. Blender 操作规范（cc2_xfbin_blender / XFBINImporter42）

### 3.1 环境

| 项目 | 值 |
|---|---|
| Blender | `G:\blender-4.2.23\blender.exe` |
| 插件 | `cc2_xfbin_blender` v1.5.0（`XFBINImporter42`） |
| patch 版插件（4.2 兼容） | `<游戏目录>\codex_blender_addon`（headless 时设 `BLENDER_USER_SCRIPTS` 指向它） |
| 4.2 需修的 4 处 API | `create_normals_split` / `auto_smooth_angle` / `calc_normals_split` / `free_normals_split`（已在 4.2 移除） |
| headless 导入 | **必须传 `files` / `directory` 参数**（模拟 GUI 行为），否则不生效 |

### 3.2 导入

`文件 → 导入 → XFBIN (.xfbin)`，选 mod 目录里的 `2karbod1.xfbin`
（例如 `...\Konan Swimsuit for Karin\Resources\Files\data\spc\2karbod1.xfbin`）。

导入后会生成一个集合（名字为文件主名，如 `2karbod1`），含：
- **骨架**（香磷 227 根骨骼）；
- **12 个部件空对象**：`body / kao / kami / eye_l / eye_r / upper teeth / lower teeth /
  tongue / udeanm / asianim` 等，各自挂着网格。

### 3.3 ★ 不许做的事

| ✘ 禁止 | 后果 |
|---|---|
| `Ctrl+J` 把所有部件合并成一个网格 | **导出时插件对每个网格对象只使用第一个材质** ⇒ 脸/头发/眼睛全贴上同一个材质；眼睛/牙齿是无权重刚性网格，合并后还会**失去骨骼定位** |
| 删除/改名 12 个部件空对象 | 结构错乱，导出后部件丢失 |
| 把眼睛/牙齿并入身体网格 | 刚性件定位失效 |
| 分散地部分缩放部件 | 部件错位；**整体缩放要选中所有部件一起缩放**，缩放基准放世界原点 |

### 3.4 导出 XFBIN（核心步骤）

`文件 → 导出 → XFBIN (.xfbin)`：

| 选项 | 设置 | 说明 |
|---|---|---|
| Collection | `2karbod1` | 要导出的模型集合 |
| File Path | mod 目录里**已存在的** `2karbod1.xfbin` | 注入模式要求目标文件已存在 |
| **Inject to existing XFBIN** | **勾选** | 保留原有贴图等内容，只更新模型/骨骼 |
| Export clumps | 勾选 | 导出骨架与部件结构 |
| Export meshes | 勾选 | 导出网格 |
| Export bones | 勾选 | 导出骨骼 |
| Export original bones | **没动骨骼就勾 / 移动过骨骼就取消勾** | 决定骨骼坐标用原值还是用 Blender 里的值 |
| Export textures / 其它 | 保持默认 | 一般不用改 |

导出完成后 mod 目录里的 `2karbod1.xfbin` 即被更新。

### 3.5 常见错误

| 错误信息 / 现象 | 原因 | 解决 |
|---|---|---|
| `Cannot inject XFBIN - File does not exist` | 注入模式的目标文件不存在（路径默认成了 `Collection.xfbin`） | 在文件浏览器里**选中已存在的** `2karbod1.xfbin`；或先把 mod 文件复制一份再导出到副本 |
| `create_normals_split` / `auto_smooth_angle` 报错 | Blender 4.2 与插件旧版不兼容 | 用已打补丁的插件版本 |
| 导出后贴图丢失 / 材质错乱 | 贴图名与材质引用不一致，或合并了网格 | 保持 Inject 模式；贴图名统一为 `2karbody` / `2kareye` / `2karcloth`；**不要合并部件** |
| 导出后模型消失 | 骨架/坐标语义变了 | 检查 `Export original bones` 的勾选是否与"是否移动过骨骼"一致 |

> ⚠️ **Blender 的注入导出会重写 XFBIN 结构**（`write_xfbin_to_path` 重建块表，
> 索引会重排、文件变长）。所以导出后**必须回读验证**，而且**不要**把 Blender 导出
> 和"字节级等长替换"混用在同一个文件上做对照实验。

## 4. 子路线 C：改顶点（五官位置 / 脸型 / 身材）

外部模型绑到目标骨架后，**眼睛/牙齿/舌头几乎一定会错位**。
根因不是"坐标算错了"，而是**两套角色的刚性网格约定不同**：

| 角色体系 | 约定 |
|---|---|
| 目标（香磷/天天等） | **骨骼放在原点，世界位置直接写在顶点里** |
| 来源（小南） | **骨骼放在头部，顶点只是骨骼局部小偏移** |

直接把来源网格配目标骨骼 ⇒ 游戏按目标骨骼变换 ⇒ **眼睛跑到脚底、牙齿跑到脖子**。

### 4.1 修法：把变换烘焙进顶点数据

1. 计算"来源骨骼矩阵 → 目标骨骼矩阵"的变换；
2. 把它**烘焙进刚性网格的顶点数据**；
3. **包围球（bounding sphere）同步烘焙**；
4. **`lod0` 与 `lod1` 都要改**（`eye_l` 与 `eye_l_lod1` 是两份网格）。

验证方式：眼睛世界 `z=1.551`、上牙齿世界 `z=1.494`，应与来源原模型**完全一致**。

### 4.2 轴向陷阱（血泪）

- 在这套模型里，**`Z` 更接近上下方向**，改 `Z` 会让眼睛往**额头/头发**方向偏；
- **真正的"内外"方向是 `Y`**：眼睛内收要沿 **`+Y`** 往脸里推；
- **必须移动完整的眼睛/表情形状**，只挪几个顶点会产生**尖刺 / 平面突起**；
- 大范围扫描式移动顶点会**误伤胸口/身体/眼睛**——不要用扫描法找嘴巴。

### 4.3 骨带旋转时的偏移反算

下牙齿骨骼带约 10° 旋转：**偏移量要按骨骼旋转反算到局部空间**，
否则世界坐标落点会偏（手鞠案例：局部 `dy=+0.77` 对应世界 `dy≈+1.02`）。

### 4.4 参考偏移量（手鞠案例，原始 NUD 坐标 = cm = Blender 米制 ×100）

| 部件 | dx | dy | dz | 说明 |
|---|---|---|---|---|
| `eye_l` | -0.49 | +0.43 | -1.79 | 含 `eye_l_lod1` |
| `eye_r` | +0.02 | +0.39 | -1.96 | 含 `eye_r_lod1` |
| `upper teeth` | -0.08 | +1.03 | -1.37 | 骨骼无旋转 |
| `lower teeth` | -0.06 | +0.77 | -1.50 | 骨骼约 10° 旋转，已反算局部 |
| `tongue` | -0.05 | +1.06 | -1.21 | 皮肤绑定 `tongue01~04` |

嘴巴（上牙、下牙、舌头）在 Y 轴往脸内**累计推进约 0.010 模型单位**，
嘴腔深度实测充足，不会穿到口腔后壁。

> **这些偏移不能机械套用到别的角色/文件。** 换角色必须**重新定位对应的 eye chunk**。
> 定位方法：在文件里按 **big-endian float** 扫描候选区间，参考筛法
> `x∈[-20,20]`、`y∈[-20,10]`、`z∈[120,175]`。
> 手鞠成功版的区间：
> `eye_l_lod0: 1923600-1925819`、`eye_r_lod0: 1925920-1928143`、
> `eye_l_lod1: 2743184-2745384`、`eye_r_lod1: 2745488-2747684`。

### 4.5 另一种"位置修正"：只移动眼睛网格坐标（天天案例）

天天替换香磷时，眼睛问题走了**两条失败路线**之后才成功：

- ✘ 改眼睛材质和贴图名（`2kareye` → `2teneye`）⇒ 眼睛透明 / 贴图丢失；
- ✘ 改低层骨架/骨骼表 ⇒ 人物姿态改变；
- ✔ **最终有效路线**：**不动材质、不动贴图名**，只移动眼睛网格坐标
  ——保持 `2kareye` 与 `c/2kar/tex/2kareye.nut`，
  只处理 `eye_l / eye_r / eye_l_lod1 / eye_r_lod1` 对应网格块的坐标。
  最终累计：**Z 上移约 +11.90、Y 往面部里约 +1.90**。
  实际调试路径：先大幅 Z 上移让眼睛从下巴到鼻子附近 → 再小幅 Z 上移到眼位
  → 最后只调 Y 让眼睛嵌进脸里。

### 4.6 嘴巴：坐标烘焙 还是 隐藏 chunk

| 方案 | 适用 | 做法 |
|---|---|---|
| **坐标烘焙**（保留嘴巴可见） | 用户明确要求保留嘴巴 | 见 4.1-4.4 |
| **隐藏 chunk**（兜底） | 坐标反复调不好、会误伤胸口/眼睛 | 把嘴巴相关 chunk 改名，让游戏不再驱动/显示 |

隐藏 chunk 的改名对照：

```
# 香磷体系
2kar00t0 tongue        -> 2kar00t0 hidden
2kar00t0 lower teeth   -> 2kar00t0 hiddenlower
2kar00t0 upper teeth   -> 2kar00t0 hiddenupper

# 校服天天体系
dtng00t0 tongue        -> dtng00t0 hidden
dtng00t0 lower teeth   -> dtng00t0 hiddenlower
dtng00t0 upper teeth   -> dtng00t0 hiddenupper
```

验证：最终文件里应能看到 `hidden` / `hiddenlower` / `hiddenupper` 仍存在，
而原 `tongue` / `lower teeth` / `upper teeth` **不再作为可见嘴部块加载**。

> **先问用户要哪种。** 手鞠案例用户要求保留嘴巴 ⇒ 走坐标烘焙；
> 天天/校服天天案例坐标调不动 ⇒ 走隐藏。

## 5. 眼睛贴图问题的两种真实根因

### 5.1 材质贴图槽数量（手鞠案例）

- 现象：模型换成功、能进战斗，但**眼睛贴图对不上**；
- 根因：**手鞠原版眼睛材质是全角色里唯一只有 1 组贴图槽的**（材质数据 64 字节），
  而香磷原版 / 天天 / Mei / 小南 / 雏田都是 **2 组贴图槽（80 字节）**；
- 修复：把 `2kareye_l` / `2kareye_r` 材质**重建为 2 组贴图槽**，引用
  `[2kareye, celshade] × 2`，与所有正常 mod 一致；
- **排除项**：眼贴图带 10 级 mipmap（699072 字节）**不是**原因
  （雏田 mod 同样带 mipmap 且正常）。

### 5.2 贴图像素格式（泳装小南案例）

- 现象：眼睛区域没有贴图；
- 排查：材质参数、网格 UV 与可用的 mod 完全一致，唯一差异是**贴图格式**——
  香磷/天天是 **RGB565（`pf=8`）**、`Nobara` mod 是 **RGBA8（`pf=17`）**、
  小南原版是 **DXT5（`pf=2`）**；
- 修复：把 DXT5 眼睛贴图**解码并转成 RGBA8 写回**（512×512，1048684 字节，
  与 `Nobara` 完全一致）。

> **诊断顺序**：先确认贴图是否"看得见"，再动坐标。
> 反过来做会白折腾（天天案例：改 `2teneye` 让眼睛透明了，问题更糟）。

## 6. 自己的 mod 打包与验证

1. 逐字节核对：**贴图数据、骨骼（coord）数据完全一致**，
   除预期改动（眼睛材质、五官顶点）外**其余材质字节完全一致**；
2. Blender 重新导入：身体/脸网格不变，眼睛/牙齿/舌头按预期偏移；
3. 写 `mod_config.ini` + `Models\<目标代码>_00|01\model_config.ini`
   （若是"保留来源前缀"路线，`BaseModel` 与文件名用来源代码；
   若是"改成目标前缀"路线，全用目标代码——**两种不能混**）；
4. 退出游戏 → NSC Mod Manager 里把该 mod **关一次再开**（重新打包 CPK）；
5. 进游戏选目标服装：选人显示 → 进战斗 → 动作归属 → 五官 → 破衣。

## 7. 本路线失败路线速记（详见 `05-troubleshooting.md`）

| 别做 | 后果 |
|---|---|
| 把外部模型重绑到目标骨架 | 选人无模型 + 进战斗崩溃（手鞠实测） |
| 用 Character Roster Editor 做成新角色 + 挂目标动作 | 选人无模型、进战斗卡加载/闪退 |
| 只把骨骼前缀改掉就套用外部骨架 | 普通攻击失效、脸型被拉大、骨骼错乱 |
| 改贴图名来解决眼睛位置 | 眼睛透明/贴图丢失 |
| 改低层骨架/骨骼表做五官微调 | 人物姿态变化 |
| 大范围扫描坐标找嘴巴 | 误伤胸口/眼睛，接缝突兀 |
| 只移动眼睛平面局部点 | 尖刺/平面突起 |
| 继续硬调嘴巴坐标 | 改到胸口或影响眼睛；不如隐藏 chunk |
